# Critique by c
## On a
Objection: a says the inode "is the guarantee", but a's cached signature belongs to an older file that is no longer linked. On ext4 the inode is reused right away. After saves A→B→C, the current file C has A's inode in every run, so a stale entry from A can match on the inode. Correctness then rests entirely on `mtime_ns` + size, which is the timestamp heuristic a's own notes call insufficient on filesystems with coarse clocks.
Grounding: `c/scratch/reuse.py` (run from c/scratch). It does a stat at A, then two atomic saves, then compares inodes: ext4 2000/2000 inode(C)==inode(A); tmpfs 0/2000. Related code: `shop/utils.py:173-176` (tmp file then `os.replace`, which frees the old inode). On this box mtime_ns is fine-grained (about 46µs steps), so no stale read happens here. A stale read needs a coarse-mtime filesystem plus two same-size saves within one tick between lookups. That would break the HARD never-stale rule, but only in a setting that wasn't reproduced.
Severity: major (the stated guarantee is false on the real filesystem; a stale read happens only on coarse-mtime filesystems)
They do better than me: a is portable (no file held open, so `os.replace` works on Windows). It also returns `deepcopy`, which protects the cache from callers who mutate the result, and it leaves `load_catalog`/`save_product` untouched. That makes it simpler and safer to adopt.
## On my own
Objection: my exactness depends on holding a file descriptor open, so the design is POSIX-only, an `open()` syscall is still made on every lookup, and `find_product` hands out the cached dict itself. That trades a robustness edge that hasn't been observed for a real portability and aliasing cost. Adding an `os.fstat` pin to a's design (or a's deepcopy to mine) would combine the two strengths.
